# 发布与敏感信息处理

本文件记录公开仓库的边界，不包含真实凭据、服务器地址或原始安全扫描报告。

## 本次处理

历史检查覆盖所有本地 Git 引用的可达对象，包括主分支、远端跟踪分支及本地辅助引用。通用 Gitleaks 扫描之外，增加了针对 GoFrame MySQL 连接串和旧 JWT 密钥的规则，并人工核对登录逻辑、部署文件和私有操作记录。

| 类型 | 处理 |
| --- | --- |
| 数据库配置与代码生成配置 | 从 Git 索引和历史中移除，保留被忽略的本地文件，提供空凭据配置示例 |
| 代码中的登录口令和固定 JWT 密钥 | 删除当前硬编码实现，历史中的原始值替换为无效占位符 |
| 真实服务器地址、部署域名、私人镜像路径与个人用户目录 | 当前部署文件改成通用配置，清洗历史中的对应值 |
| 作者和提交者的个人邮箱 | 替换为仓库所有者对应的 GitHub noreply 邮箱，保留姓名、时间与说明 |
| 本机诊断脚本、带账号及运行状态的排查记录 | 从索引和历史移除，保留本地副本 |
| 证书和私钥 | 原有证书目录未被跟踪；添加全局忽略与 Docker 构建白名单，TLS 文件改为运行时挂载 |
| 日志、截图缓存、运行目录、数据库备份和构建产物 | 扩展 `.gitignore`，不纳入发布内容 |
| README 截图 | 使用真实 Vue 组件与模拟数据，不读取真实账号或游戏截图 |

当前鉴权需要从本地配置或环境变量读取随机凭据，缺少有效配置时拒绝启动。JWT 只接受 HS256、必须带有效期，并且用户必须存在于当前配置。登录用户名绑定到对应 MAA 实例。

定时任务更新、删除和立即执行接口按当前登录用户过滤；WebSocket 使用默认的同源检查，HTTPS 页面使用 WSS。开发服务器默认仅绑定回环地址，示例后端配置不启用公开 API 文档。

## 配置迁移

旧配置需要增加 `auth`，字段见 `manifest/config/config.example.yaml`。为 JWT 和各账号生成独立随机凭据，并将用户名与 `maa.asst[].id` 对应。新代码不会继续接受旧代码中的固定登录口令。修改配置与密钥后需要重启程序，当前浏览器应重新登录。

初始化脚本不会覆盖现有配置。现有部署可手工合并 `auth`，也可通过 `MAA_JWT_SECRET` 与 `MAA_LOGIN_TOKENS` 设置凭据。实际凭据只能保存到被忽略的本地配置、受控环境或秘密管理系统。

必须沿用旧登录口令和未过期 JWT 的私有部署，可显式设置 `auth.allowlegacycredentials: true`，并把原登录映射和原签名密钥移到本地 `auth` 配置。此选项沿用旧凭据的强度，默认关闭；空凭据、重复用户及重复令牌仍会被拒绝。公开示例和新部署继续要求至少 32 字节的独立随机值。

旧前端部署参数可以保存在被忽略的 `web/.env.local`、`web/deploy.local.json` 和 `web/*.local.conf` 中。开发监听参数支持 `DEV_SERVER_HOST`、`DEV_SERVER_PORT`、`DEV_SERVER_ALLOWED_HOSTS`；镜像推送脚本可从 `deploy.local.json` 的 `imageRef` / `certImageRef` 读取本机目标。Nginx 私有配置应在运行时挂载，不会被复制进公开镜像。

## Git 历史和备份

历史清洗前建立了包含所有原始引用的私有 Git bundle，并验证了备份。备份位于仓库外，具体路径在本次操作的本地报告中。它仍包含原始敏感内容，只用于受控恢复，不能上传到 GitHub、Release、网盘公开链接或容器仓库。

清洗会改变相关提交及其后继提交的哈希；仅修改 `.gitignore` 无法解决历史泄露。发布时只推送需要的分支，避免将私有备份、旧克隆或未清洗的引用重新带入仓库。

本地两个无受跟踪改动的旧辅助工作区也已切换到对应的脱敏提交。旧远端配置保存在私有本地报告中，并已从当前仓库断开，避免后续误拉取旧历史；发布时应重新添加经过确认的目标远端。

如果远端已经包含旧历史，应先轮换曾入库的数据库密码、登录凭据及签名密钥，再按 GitHub 官方流程更新远端历史，并处理旧克隆、分支、PR 或缓存。普通追加提交无法撤回旧凭据，强制推送也不能删除别人已经保存的副本。参见 [GitHub：从仓库移除敏感数据](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。

本地清洗不代表 GitHub 上的历史已同步更新。任何远端强制更新都需要协调已有协作者，并使用明确分支和正确的 lease 条件；不要盲目执行 `git push --mirror` 或无条件覆盖远端。

## 每次发布前检查

```powershell
git status --short
python scripts/audit-publication.py --history
gitleaks git --redact=100 --log-opts=--all .
```

[项目检查脚本](../scripts/audit-publication.py) 检查候选文件与所有可达历史 blob，只输出路径、行号和问题类型，不输出秘密。它覆盖本项目已发现的模式，需与 [Gitleaks](https://github.com/gitleaks/gitleaks) 及人工审查配合，不能保证发现所有形式的秘密。

检查 `git diff --cached --name-status` 确认只有公开源码、示例配置和文档被提交。不要公开原始扫描报告或用 `git add -f` 加入已忽略配置。依赖安全更新和应用的持续安全审查仍需单独维护。
